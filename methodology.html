Methodology & Limitations

← back to dashboard

This page exists so anyone reading a lead can audit how it got there. It documents the data sources we pull from, the six distress patterns we score, the tier-assignment rules, the sources of noise we know about, and what isn't included and why. Read this before trusting a lead enough to pick up the phone.

What this is

A flat-file pipeline that joins public records from Mecklenburg County, NC and the City of Charlotte, then surfaces parcels where multiple distinct distress signals stack on the same property. The output is a single data/leads.json file consumed by a static dashboard. Everything here is open data — no PII beyond what already appears in public records.

The six-pattern stack

Each distress signal collapses into one of six pattern categories. A parcel's tier is determined by how many distinct categories hit it (the stack depth) — never by the raw score sum. Stacking orthogonal signals is the whole point: a parcel in foreclosure that's also got an open code case and a recent quitclaim is a much stronger candidate than a property with three different code violations.

JFC Judicial Foreclosure

NC is a judicial-foreclosure state. Fires on:

  • Mecktimes notice with an SP-numbered case (Special Proceeding) and "Foreclosure of Deed of Trust" / "Power of Sale" language
  • Substitute-trustee sale notice in mecktimes
  • (When ROD data is wired) — recorded "Notice of Substitute Trustee Sale"

TAX Tax Distress

  • Active case at Kania or RBCWB (PID join)
  • Mecktimes notice with "Mecklenburg County" as plaintiff (In Rem under GS 105-375 or mortgage-style under GS 105-374)
  • Mecktimes notice explicitly tagged "TAX FORECLOSURE"

ESTATE Probate / Estate Opened

Notice to Creditors filed in mecktimes' probate index; decedent name matched against POLARIS owners.

Known noise: matching is by decedent name, not by parcel id. A common-surname-only notice (e.g. "JOHN SMITH") would attach to dozens of unrelated parcels, so we
  • require last + first + middle when the notice has it (3-word match keys),
  • fall back to last + first only when the surname is ≥5 chars AND not in the top-50 US surnames list,
  • skip the notice entirely if neither condition holds.
Even with this filter, the same name can match multiple unrelated owners. Verify identity before contact.

CODE Code Violation / Demolition

  • Charlotte HNS case with CaseStatus = Open or New (Closed cases are excluded — 99% of historical cases are closed and stretch back years; they aren't a current motivation signal)
  • Sub-flag code_housing_case when CaseType is Housing (vs Nuisance, Sign, etc.)
  • Sub-flag code_repeat_violator when 2+ open cases on the same PID
  • Sub-flag demolition_order when present in the Orders to Demolish layer (~21 active)

Coverage gap: City of Charlotte only. Cornelius / Davidson / Huntersville / Matthews / Mint Hill and unincorporated areas use Mecklenburg County's separate code.mecknc.gov system, which has no open-data feed.

LIEN Recorded Lien / Civil Judgment

  • Mecktimes notice with HOA-claim-of-lien language
  • Civil execution sale (CV-numbered case, sheriff's execution for unpaid debt)
  • (When ROD data is wired) — Memo of Judgment, Mechanics Lien, IRS / state tax lien, Lis Pendens

TRANSFER Distressed Conveyance

Two sub-rules — either fires the pattern:

  • Rule A — recent sale (within 24 months) at nominal consideration: sale price < $1,000 OR < 5% of total market value. This is the common shape of an heirship deed, a deed-in-lieu of foreclosure, or a non-arms-length family transfer.
  • Rule B — estate notice posted within 18 months PRIOR to a parcel sale. The decedent died, an estate was opened, and the property sold within 18 months.

Rule B order matters: a sale that predates the estate notice doesn't fit the pattern. We check that the estate posted_date is ≤ the sale_date.

Tier rules

  • HOT — 3 or more distinct patterns stacked on the same parcel
  • WARM — exactly 2 patterns
  • ACTIVE — exactly 1 pattern
  • Parcels with zero patterns are not emitted as leads.

Sub-flags (absentee_owner, demolition_order, code_repeat_violator, heirs_property_indicator, nominal_consideration_recent_sale, etc.) add to a lead's distress_score for in-tier sorting but never promote tier. A 1-pattern lead with five sub-flags is still Active. Stacking different categories is the only path to a higher tier.

This is a deliberate anti-inflation rule. It's easy to drift into a system where each new sub-rule adds points until everything is "Hot" because the score is so generous. Tier-from-stack-depth makes that impossible.

Derived fields on every lead

  • estimated_equity_pct — 1 - sale_price / total_market_value, bounded 0-100. Rough floor estimate of paydown + appreciation. Real equity requires the current loan balance, which lives in ROD.
  • years_owned — years since last sale per POLARIS.
  • is_absentee — mailing-address street name doesn't match the site address street name.
  • is_likely_landlord — absentee + non-entity individual, OR an entity name containing rental/properties/holdings/realty.
  • is_homestead, is_senior, is_disabled_veteran, is_disabled — POLARIS exemption flags.
  • is_likely_inherited — held ≥25 years AND structure age ≥50 AND owner not an entity AND not homestead-exempt. Soft hint, not a hard signal.
  • lot_value_pct — land value / total value. High = land play / teardown candidate; low = meaningful improvements.
  • distress_score — pattern count × 10 + flag count + small bumps for absentee / senior / equity ≥ 50% / years_owned ≥ 20. Used only for in-tier sorting.

Anti-bot blockers we hit

Mecktimes (Cloudflare TLS fingerprint): the live scraper at scrapers/foreclosures.py and scrapers/estates.py is blocked from the build machine even with curl_cffi impersonating Chrome. The seed data for both was extracted via a side-channel renderer. The scraper detects the 403 and exits cleanly without overwriting data on disk. Workarounds documented in scrapers/README.md.
Aumentum / Mecklenburg Register of Deeds: meckrod.manatron.com is fully login-gated. Phase 3 reconnaissance confirmed all search paths return "Session state is not available" unauthenticated, default guest/guest credentials fail, and there is no documented public account on this deployment. The pipeline ships with a CSV-import path (scrapers/rod.py) so a logged-in human export can hydrate the lien / quitclaim / DOT signals — until that data exists, the lien pattern only fires from mecktimes HOA notices and CV-execution sales (5 records in this build), and transfer fires only from POLARIS sale heuristics.
eCourts (Tyler Odyssey): CAPTCHA-gated and rate-limited. Not scraped. Newspaper notices in mecktimes cover the events (foreclosure sales, estate openings) that go to public notice by statute, with a 1-7 day publication lag.

What isn't included and why

  • Register of Deeds full coverage — no live scrape (login wall, see above). This caps the lien and transfer patterns and is the single biggest gap. Hot-tier leads (3+ patterns) become abundant once ROD data is loaded.
  • County code enforcement (towns + unincorporated) — code.mecknc.gov has no open-data feed. We only see the City of Charlotte HNS data.
  • Annual delinquent-tax PDF — published once a year. Not parsed. The active-foreclosure flow (Kania + RBCWB) covers the higher-signal subset (delinquents whose case has progressed to a filing).
  • eCourts case detail — see CAPTCHA note above. We get the public-notice slice; we don't get the underlying SP/E filing detail.
  • Skip-trace / contact info — phone numbers, email addresses, current employers, deceased flags. Out of scope for a public-records pipeline. The CSV export includes empty phone1/phone2/phone3/email1/email2 columns so a downstream skip-trace vendor can fill them.
  • MLS / valuation models — no Zillow / Redfin / RPR / RentCast. Tax-assessed values from POLARIS only.

Honesty about precision

This is a POC built over a few sessions on public data. Some specific noise sources you should know about:

  • Estate matching — fuzzy name match attaches the average decedent to roughly 3.4 parcels. Some of those are correct, some aren't. Always verify identity before outreach.
  • Foreclosure address match — about 75% of mecktimes notices match a POLARIS parcel by address. The rest fail because of unit/condo numbering, abbreviation differences, or out-of-county notices that slip through the county filter.
  • POLARIS multi-row history — the CAMA layer has multiple rows per parcel (revaluation history). The pipeline keeps the first row per PID. A more correct approach is to keep the most recent yearid; that's a follow-up.
  • Tax foreclosure mailing addresses — Kania / RBCWB don't include mailing address; we get owner name and parcel ID. Mailing comes from POLARIS via the PID join.
  • Code-case Closed cases excluded — 99% of historical HNS cases are Closed. Including them inflated code matches to 122K parcels, with most being years-old nuisance complaints. Open/New only is a deliberate trade-off favoring precision over recall.

Two-Truths invariant

The dashboard's filter counts and filtered table are both derived from a single matches(lead) function — same call, same input array, same output set. Every render is one filter pass; the stat cards and the visible rows can never disagree. This is the canonical mistake the framework spec warns against (the "Two-Truths Bug"); we check it on every pipeline run.

Scope and intent

This is a test-run product, not a sold service. Built across a few sessions to validate the Texas framework on a North Carolina judicial-foreclosure jurisdiction with a different doc-type vocabulary. The structural pieces — POLARIS pull, joining, six-pattern stack, dashboard, methodology page, CSV-import for ROD when login becomes available — are reusable across any NC county whose data sources resemble Mecklenburg's.
